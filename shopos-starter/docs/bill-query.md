# Bill search, detail, and proof access

`GET /bills` requires `bills:read`. Owners have all permissions. Employees with this grant can search shared shop bills, including bills entered by other employees. This matches the counter workflow where staff need to find a purchase regardless of who recorded it. There is no owner-only filter in Q06.

The optional query parameters are `vendor`, `item`, and `employee` (case-insensitive text); `date_from` and `date_to` (inclusive `YYYY-MM-DD` dates); `amount_min` and `amount_max` (inclusive total amounts); and `limit` (1–100, default 30) with `offset` (0–10000). Vendor and item text match canonical names or aliases; employee text matches display name or username. All supplied filters are combined with AND. Amounts compare against the final payable total. Results are sorted by bill date, creation time, then ID, newest first. The response has `rows` and `has_more`; each row includes vendor, employee, item names, date, and total. Invalid ranges return 422. `GET /bills/{id}` returns ordered item lines, source price basis, amounts, creator, proof ID, and totals; unknown IDs return 404.

Linked proof metadata and `GET /attachments/proofs/{id}/download` follow bill readability. A user with `bills:read` can obtain a short-lived signed URL for any linked proof. A linked proof is denied to an employee without bill-read permission, even if they uploaded it and still have `attachments:read`. An unlinked upload remains visible only to its uploader with `attachments:read`; the owner can access either. Proof bytes are fetched from private object storage only after the user requests the photo. The API never exposes private object keys or permanent URLs.

The Android Find bills screen submits all filters to the server, loads 30 rows at a time, opens detail, and requests a signed proof URL on demand. It does not cache proof bytes or search results locally. Q06 needs no schema migration: it reads Q03–Q05 tables and preserves PostgreSQL as the source of truth.
